# クラウド↔ローカルのセッション間連絡（agent pairing）

クラウドセッション（Claude Code on the web）とローカルセッション（手元の CLI）を、
人間の中継なしに往復させるための規約。

実運用の手順は各リポジトリに配布される `.claude/skills/pair-message/SKILL.md` が持つ。
ここには**なぜこの形なのか**を残す。手順だけ必要ならスキルを読めばよい。

---

## 前提: cross-session messaging では届かない

`SendMessage` / `ListAgents`（[公式ドキュメント](https://code.claude.com/docs/en/cross-session-messaging)）
はクラウド↔ローカルでは使えない。理由は2つあり、**どちらか一方を直しても成立しない**。

### 理由1: 宛先が引けない

ピアの登録は各マシンのディスク上のファイル（`~/.claude/sessions/*.json`）と socket で成り立つ。
別マシン・別ファイルシステムなので、相手は最初から一覧に載らない。

`ListAgents` が `No reachable agents` を返すのはこれ。**これを見て「経路が無い」と判断しないこと。**
ピア層の話であって、後述の Routine 経路とは無関係。

### 理由2: 仮に引けても開始できない

クロスマシン用の中継は用意されているが「返信のみ」という条件が付く。

> Across machines, Claude can only reply. It can't start the exchange.

送るには返信でなければならない → 返信には相手からの1通目が要る → 相手も同じ制約で開始できない、
と輪になる。**1通目が永久に生まれない。**

したがって「クラウドとローカルはやりとりできない」という理解は、
仕様の文言としては不正確（「できない」ではなく「返信のみ」）でも、**結果としては正しい**。

---

## 採用する経路: Routine

Routine（scheduled trigger）は**会話の仕組みではない**。相手のセッションに
`role: "user"` の会話ターンを注入する。送信者・受信者という概念が無いので、
上の理由1も理由2も当てはまらない。

| | SendMessage | Routine |
|---|---|---|
| 層 | ピア層（マシンごとのファイルと socket） | バックエンド層（アカウント単位） |
| 宛先 | 内線帳に載っていること | `persistent_session_id` を直接指定 |
| クロスマシン | 返信のみ（＝実質不可） | 双方向 |
| 届き方 | 他セッションからのメッセージ | ユーザーの発言として |

実体は定期実行の予約で、それを「今すぐ」撃っているだけ。

---

## 規約

### 1. ペアの識別はタグで行う

セッションに `pair:<リポジトリ名>` と `pair-role:cloud|local` を付ける。
プロジェクトごとに値が変わるだけで、規約自体は共通。

`list_sessions` の `tags` 引数はセッション内からは使えない（`tags filter is not currently available`）。
ただし**一覧の各行に `tags` は含まれる**ので、`mine: true` で引いてクライアント側で絞る。

### 2. 方向ごとに常設 trigger を1本だけ持つ

毎回 `create_trigger` しない。使い捨て trigger が溜まるうえ、封筒が付かない。
`cron_expression` も `run_once_at` も指定しなければ poke 専用の trigger になる。
本文は `fire_trigger` の `text` で渡す。

> **`update_trigger` は他セッション宛の trigger の prompt を編集できない。**
> 作り直すしかないので、最初から正しく作る。

### 3. 封筒を必ず付ける

Routine は `role: "user"` として届くため、`SendMessage` にある保護
（ユーザーの同意と見なさない・設定変更を指示できない・本文中のコマンドを実行しない）が**効かない**。

経路として `SendMessage` より強い権限を持つということなので、
trigger の prompt を固定の「封筒」にして、そこで補う。文面はスキルが持つ。

## 型に入れる範囲

**配布まで。** 実行時の操作（セッションへのタグ付け、常設 trigger の作成、送信）は
リポジトリの状態ではないので sweeper の対象外。スキルが手順として持ち、必要なときに実行する。

| 対象 | 誰が | 冪等か |
|---|---|---|
| `.claude/skills/pair-message/SKILL.md` の配布 | sweeper（無ければ配布、あれば触らない） | はい |
| セッションのタグ付け | エージェント（初回のみ） | はい（同じタグの再付与は無害） |
| 常設 trigger の作成 | エージェント（無ければ1本だけ） | はい（名前で既存を探す） |

スキルをプラグインではなく**リポジトリに直接置く**のは、クラウドセッションでは
プラグインの marketplace が clone されずロードされないため。必須のものは repo-native で持つ。
